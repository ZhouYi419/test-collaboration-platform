# UI Skill 与本次设计偏差复盘

日期：2026-11-18。记录修订前的问题、修订依据和验证结果。

## 判断与证据边界

当前设计与测试、开发高频处理事项的产品气质存在偏差。问题来自产品定位到视觉决策的转译、验证顺序以及后续继承，不能只归因于某一种颜色，也不能用功能测试通过代替视觉适配。

本轮依据：

- 修订前的 `design-product-ui/SKILL.md`，重点为「设计依据」「视觉方向与质量标杆」「主视觉与图片」「按功能逐步设计」「预览与交付前自审」。
- 仓库 `docs/PRD.md`、`docs/UI_DESIGN.md`、`docs/TASKS.md`、T002–T004 原型覆盖记录及当前前端代码。上一轮实看了登录页；本轮以代码和设计记录审查全范围，没有重新操作所有线上状态。
- 历史会话摘要表明，用户从早期就要求每页匹配整个项目定位；登录及后续账号管理曾分别获得确认，之后扩展到事项业务。这是对历史记录的归纳，不是逐字原始对话。

旧版 Skill 曾经过多轮补充。可以确认“小雀核对清单”曾被写进通用 Skill，加入时间与最初设计之间的关系缺少证据。

## 偏差是怎样累积的

1. **先用入口页建立印象。** 已有材料按登录注册、账号管理、事项功能依次展开；暖白深绿与插画作为早期方向进入 UI 规范。没有找到用主要事项工作流对整站方向进行对照验证的明确记录；这不等同于证明历史上从未讨论过工作区。
2. **局部认可被扩展为整站依据。** UI 规范在 T003 明写复用暖白、深绿，T004 继续沿用工作台。登录或账号页的确认有其当时范围，不能充分证明同一方案适合长表单、复杂详情与日常工作队列。
3. **后续复审主要修局部。** 原型记录包含间距、双边线、详情宽度、窄屏提示遮挡、焦点和重试的实际改进。这些工作有价值，但回答的是“该页面是否整齐、可操作”，没有充分回答“整组页面是否体现合适的产品气质”。
4. **技术通过被当成强烈完成信号。** 构建、权限、并发、页面主流程通过能证明相应功能，不能证明风格适配。既有任务完成记录应保留，本次视觉满意度需要单独重新建立证据。

上述是记录支持的过程及其合理推断，不能据此把责任转给用户曾经确认某版稿。设计执行者有责任解释局部确认的边界、发现整体失配并提出验证。

## Skill 已经具备、执行仍然不足的部分

不能把现有 Skill 说成完全没要求产品适配。它明确要求依据定位、使用场景、信息密度设计，也明确要求高频工具页利于扫读和操作；还要求查看真实内容、窄屏和整页路径。因此有两类问题必须同时处理：

- **方法缺口：** 缺少代表页选择、确认边界、跨页方向验证和方向重评条件，容易让抽象要求停留在口号。
- **执行遗漏：** 没有充分把核心研发工作页作为风格依据，没有持续检验整站气质。仅把“以总监视角再看一遍”写得更重，不会自动解决。

“像 Apple／米哈游一样精细”可以作为完成度追求，不能作为审查通过证据，更不能替代适合当前产品的设计理由。不应把参考品牌的外观直接套进所有产品。

## 修订时采用的通用规则

以下是从本次问题提取的通用规则。实际 Skill 按工作阶段组织这些规则。

> 方向建立前，将产品定位转为具体设计依据：主要使用者、使用频率、核心任务、内容与数据密度、品牌气质，以及它们对构图、排版、颜色和素材的影响。每个关键视觉选择应能通过代表性页面和真实内容验证。

> 代表页应来自产品的核心任务。当前功能若是登录、设置等辅助入口，不能仅凭该页面确认全站风格。按产品风险补充不同密度或不同操作类型的页面，对照验证同一视觉语言；未来业务细节未确认时只验证页型与布局，不虚构正式业务规则。

> 记录视觉确认的范围与未验证项。后续页面沿用的是已经证明合适的规则；出现新页型、明显密度变化、品牌气质冲突或用户反复否定整体观感时，先重评通用方向，并说明保留与调整的依据。

> 交付前分别检查产品适配、视觉质量、交互可用性。产品适配检查核心任务、信息密度与品牌是否相称；视觉质量检查层级、构图、字体、颜色职责和跨页一致性；交互可用性检查实际操作、适配、反馈与恢复。各项报告实际证据，不以任一项通过代替其他项。

> 项目素材、题材、品牌色及特定页面数值保存在项目 UI 规范。通用 Skill 只保留可迁移的选择方法和验收方法；单次复盘先区分项目约束、方法缺口和执行遗漏，再决定是否修改 Skill。

> 减少装饰时检查是否同时丢失分组、导航、状态或操作线索。保留能够帮助完成任务的结构，避免将克制等同于低对比、小文字、大片留白或连续分隔线。

## 修订与验证记录

此前的审核遗漏发生在把项目复盘写回通用规则时。判断材料能否入 Skill，应检查它是否改变多个场景的设计决策。具体题材可用于解释项目历史，跨项目可验证的方法才适合写入通用指令。

UI Skill 全文重新审查。删除单项目素材、业务角色和具体交互的举例，移除用品牌名和审查者身份代替设计证据的表述，也移除 UI 工作自动触发 Skill 写入和归档同步的条款。项目素材及参考留在项目规范，命名与项目交接按相应的规划流程处理。

独立纸面演练检验了两类任务。排班工具选择班表和异常编辑验证扫读与操作，登录只验证入口。双语摄影档案选择照片网格与图注详情验证构图、裁切和双语阅读。根据演练反馈，明确原型在浏览器中复查渲染，产品从正常入口验收，并补充按内容核对无障碍语义。演练验证的是选择方法，实际页面质量由项目原型评审验证。

任务规划 Skill 增加插入与重排规则。重构放到实际需要执行的位置，标明对下游任务的依赖。按用户指定的顺序编号时，检查可顺延范围、历史记录及各处引用。本项目按 [全页面重构计划](UI_REFACTOR_PLAN.md) 先验收 T005，再进入 T006。

两份修订已安装到本机。已核对 UTF-8、文件头、项目残留用语和安装后的文件哈希。官方验证脚本所需的 PyYAML 在当前环境不可用，本次用独立结构检查验证了这两份仅含名称和描述的文件头。任务卡、阶段编号、文档引用与已完成任务记录也已核对。

## 第二轮修订

首轮压缩弱化了既有质量标准。按用户确认，以归档仓库 `9a76807` 的 UI Skill 为底稿修订。逐条对照结果是只删除一条项目素材示例，保留 Apple 产品级精细度、首轮独立视觉复审，以及交互、动效、窄屏和截图取证规则。新增三条，分别明确代表页选择、确认范围和分项复审证据。GitHub `main` 的 `3fa90e6` 与本机内容已核对一致。本次同步仅涉及 UI Skill。

## 核心页细节复审的遗漏

此前已查队列宽度、反馈失败与成功、返回原记录等关键路径。三处遗漏来自选取的观察点。

- **列表的视觉负担累积。** 单行的状态标签和箭头有含义，整列反复强调时与优先级争抢注意力。对照同类与混合列表，在真实密度样本中检查保留必要信息的方式。
- **等待过程中的位置。** 反馈测试检查了失败时的输入、提示和重试按钮，却漏看「提交中」的按钮外框。复查发现按钮缩窄约 29 像素。验收要在同一视口对照操作前、等待中和结果出现时的位置及可用性。
- **写入后的落点。** 从详情返回原记录与保存后返回变更记录有不同目标。原验收覆盖前者，也验证了处理反馈成功后的只读结果。草稿保存后仍需检查用户是否找到具体记录，特别是在同名或排序变化时。

上述做法已增补到本机 UI Skill 的三条既有规则。逐项逆向核对时，移除三处新增文字可逐字恢复修改前文件。界面复测结果见 [核心页面复审](prototypes/t005/核心页面复审.md)。

## 下拉控件展开态的遗漏

全套原型最初统一了闭合控件的样式，但浏览器仍使用系统风格绘制展开菜单。上一轮用自动化直接选择选项来验证字段联动和保存，截图集中在页面和弹层，未对单独展开的选项面板截图复审。选值正确只说明表单行为通过。

本机 UI Skill 在现有独立复审章节新增一条展开态检查。通过正常操作展开菜单或选择器，核对视觉一致性、选中与焦点、窄屏位置及遮挡。定制优先复用可定制的原生控件或已有组件。逐字节核对确认只增加此条。本项目的原生选择控件样式和实际浏览器复测见 [下拉控件细节复审](prototypes/t005/状态覆盖与验收.md#下拉控件细节复审)。
