# T008 消息通知原型

从[我的事项](index.html)点击头像左侧的铃铛。桌面在铃铛下方展开约 384 像素宽的浮层，窄屏从底部展开消息。关闭后可继续当前事项。

| 场景 | 入口 | 可检查的结果 |
| --- | --- | --- |
| 测试侧消息 | [测试消息](index.html?panel=1#tester/issues) | 领取、开始处理和处理结果待验证。重复反馈按各轮显示。铃铛显示未读数，消息按发生时间倒序。 |
| 开发侧消息 | [开发消息](index.html?panel=1#developer/issues) | 指派、验证退回和验证通过。打开退回消息，可在事项详情查看原因。 |
| 查看和已读 | [测试消息](index.html?panel=1#tester/issues) | 详情加载成功才标为已读。返回时回到原任务，可再次点铃铛查看。「全部标为已读」同步更新角标。 |
| 查找更早消息 | [多批消息](index.html?panel=1&case=more#tester/issues) | 默认展示最近 6 条。只在还有历史时显示「加载更早消息」。点开后保留已显示记录，焦点移到第一条新加载的消息。 |
| 编辑时收到提醒 | [开发正在编辑](index.html?case=arrival#developer/work) | 约 2.4 秒后模拟收到退回提醒。打开或关闭消息面板仍可保留输入和滚动位置。点击具体消息准备离开时，未提交的说明触发原有确认，取消后继续编辑。 |
| 同时收到多条 | [测试事项](index.html?case=burst#tester/issues) | 三条消息合并成一个提示，点击就地打开面板。面板已打开时更新消息列表和角标，并保留当前行的键盘焦点。 |
| 加载、空状态、读取失败 | [加载中](index.html?panel=1&case=loading#tester/issues) · [空状态](index.html?panel=1&case=empty#tester/issues) · [读取失败](index.html?panel=1&case=load-error#tester/issues) | 反馈分别显示在面板内。读取失败可在原位置重试。 |
| 标记失败 | [批量](index.html?panel=1&case=read-error#developer/issues) · [单条](index.html?panel=1&case=read-one-error#developer/issues) | 批量标记失败可在浮层重试，原未读状态保留。单条标记失败可继续查看事项并重试。 |
| 详情读取失败或不可用 | [重试详情](index.html?panel=1&case=detail-error#tester/issues) · [事项不可用](index.html?panel=1&case=unavailable#tester/issues) | 点第一条消息。读取失败或事项不可用时保留未读数。读取失败可重试。 |
| 访问受限 | [管理员视角](index.html#admin/issues) | 管理员工作区隐藏消息铃铛。 |

## 浏览器复审

- Chrome 1440 × 900 和 850 × 700 检查头像与铃铛的位置、浮层锚点、工作区保留和标题换行。在相同的 1440 × 900 视口，对照上一版整页列表和新版原事项上方的浮层。实际验证键盘开启、Tab 移到消息、Escape 和点外关闭、焦点回铃铛、单条及批量已读、返回原任务、历史加载和打开面板时的新消息。
- Edge 390 × 844 和 320 × 740 检查底部面板，验证遮罩、关闭后恢复滚动、编辑输入保留、取消和确认离开、多条提示、空态、读取及标记失败重试、减少动态效果，代表状态无横向溢出。
- 复拍前修正桌面按 Tab 时浮层过早关闭，以及 320 像素下背景事项标题被截断的问题。复测确认 Tab 进入第一条消息，窄屏事项标题完整换行。
- 原型用定时器模拟消息，刷新后恢复初始样本。正式版前台检查间隔拟为 5 秒。实际事件入库、并发去重、权限隔离和多会话同步在实现阶段验收。Firefox、实体手机软键盘和完整读屏待实测。
