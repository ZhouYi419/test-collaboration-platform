[开发侧预览](index.html) · [测试侧预览](index.html#lin/items) · [在同页切换角色](index.html?review=1)

演示账号为测试林溪，以及开发陈砚、何启。「在同页切换角色」入口会显示评审用的身份栏，便于在同一数据集上验证角色联动。记录和文件保存在当前页面内存，刷新后恢复示例。

| 状态或流程 | 操作入口 |

处理说明在原型中沿用 5,000 字符上限。领取竞争、候选账号失效、附件可见范围和网络失败使用模拟状态，真实事务、角色鉴权和接口重试在产品实现后验收。

Chrome 1440 × 900 和 Edge 390 × 844 已走通指定、领取和反馈路径。复测了日志下载、模拟抢领、访问受限、无候选、失效候选、空说明、写入失败后重试、Escape 关闭和返回列表焦点。另检查了 Edge 320 像素下的列表、表单和详情溢出。

视觉复审前后在相同视口截图。复测了收紧后的分类与列表间距、详情标题和摘要、指定开发控件对齐、320 像素下处理说明与重试操作同屏、键盘聚焦附件时整行滚到操作栏上方，以及提交后聚焦只读反馈。

独立复审补查成功提示出现的瞬间。320 像素下原悬浮提示会压到反馈末行，现将成功提示放在处理反馈标题旁。评审身份切换的三个选项在窄屏同排。Chrome 1440 像素和 Edge 320 像素同状态截图对照通过，另在 Edge 390 像素重跑指派和反馈主流程。

宽度复审在同一视口从列表打开详情并前后复拍。Chrome 1280 像素下，详情相对主工作区的左右留白由约 71 / 216 像素变为 71 / 71 像素。1440 像素下，详情与列表同宽 960 像素，长正文保持 760 像素。Edge 390 和 320 像素下检查了长标题换行、详情两侧对齐及底部操作，指定、领取、反馈和重试流程复测通过。
