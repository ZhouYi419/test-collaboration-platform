# T006 测试验证与重新处理原型

从[我的事项](index.html#tester)打开 Bug 或需求。可以直接验证通过，也可以输入原因退回，再从页面底部的评审控制切换到「打开开发待办」。用原负责人身份提交新说明后，切回测试复验。角色切换在同一标签页保留模拟结果。

| 场景 | 入口 | 可检查的结果 |
| --- | --- | --- |
| 首轮验证、关闭 | [测试列表](index.html#tester) · [待验证 Bug](index.html#tester/report) | 查看反馈，通过前可取消确认。关闭后详情只读，显示验证人和时间。返回列表定位原事项。 |
| 退回与校验 | [待验证需求](index.html#tester/copy) | 点击「验证不通过」展开表单。提交空原因后定位输入框。填写原因并退回后显示「处理中」和验证结果。 |
| 重新处理 | [开发待办](index.html?case=returned#developer/assigned) · [重新处理详情](index.html?case=returned#developer/assigned/report) | 原负责人先读到退回原因和上次反馈，可直接填写新说明。提交后状态为「待验证」，焦点移到处理反馈。 |
| 再次验证 | [测试复验详情](index.html?case=reverify#tester/report) | 新处理反馈和「上次验证」分区。可再次退回，也可通过。 |
| 关闭后查看 | [测试关闭详情](index.html?case=closed#tester/report) · [开发已反馈队列](index.html?case=closed#developer/feedback) | 双方可读已关闭事项及验证结果。 |
| 提交中、失败与重试 | [退回失败](index.html?case=write-error#tester/report) · [处理反馈失败](index.html?case=write-error#developer/assigned/snapshot) | 首次提交显示等待态并模拟网络失败，保留输入。重试可成功。 |
| 事项已更新 | [旧页面提交](index.html?case=conflict#tester/report) | 填写退回原因后模拟另一处已关闭事项。输入值保留供查看，重新加载后聚焦最新结果。 |
| 访问受限 | [其他测试账号](index.html#colleague/report) | 显示事项不可用并提供返回列表入口。 |
| 加载、空和读取失败 | [列表加载](index.html?case=loading#tester) · [已反馈空态](index.html?case=empty#developer/feedback) · [详情加载失败](index.html?case=load-error#tester/report) | 可查看加载提示、空队列及读取失败，重新加载可恢复详情。 |

## 浏览器复审

- Chrome 1440 × 900 从列表进入详情，核对了工作区左右边线和返回焦点。走通 Bug 直接关闭、关闭确认的 Escape 取消、开发查看只读关闭详情，以及需求连续两次退回和重新反馈再关闭。模拟数据中三条验证结果分别对应三份处理反馈。
- Edge 390 × 844 检查了详情跳转、底部确认面板、退回原因与重提反馈、提交成功时的焦点。320 × 740 组合检查长原因、网络失败、重试、冲突重新加载、访问受限、读取失败、空态和减少动态效果。窄屏复拍确认失败时输入、提示及主要按钮可同时看到，重新加载入口与旧输入相邻。桌面和窄屏代表性截图均无横向溢出。
- 原型使用浏览器内的模拟角色、状态和写入。真实 API 鉴权、数据库记录、并发与事务留在实现后验收。实体手机软键盘、Firefox 和完整读屏待验收。
