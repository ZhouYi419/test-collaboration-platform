# 功能卡片与实施顺序

状态：2026-11-15 更新
依据：PRD v0.2 和已确认的技术组合。按各卡片记录的状态和验收标准执行。每次交付同步设计和执行适当的功能、接口、权限及自动化检查，并记录真实缺陷；不等所有业务结束再测试。

## 业务主线
测试人员提交 Bug 或需求 → 指定开发或由开发领取 → 开发处理并反馈 → 测试验证，通过后关闭或不通过后退回。

## 任务卡

### T001｜注册、登录与退出（已完成）
- 关联：F001；依赖：无。
- 目标与范围：用户能注册、登录和退出；建立应用运行、数据库及基础测试方式。
- 非目标：完整用户管理、角色和业务功能。
- 注册验收：四项必填；邮箱格式、密码长度、密码一致及账号标识唯一性由服务端校验。有效提交后展示等待启用提示和返回登录入口。
- 登录验收：错误凭据显示统一提示；正确凭据的待启用账号提示联系管理员。管理员运行启用命令后，用户名和邮箱均能登录并访问账号页。
- 会话验收：未登录、已退出和已过期的会话访问受保护接口返回 401。刷新保留有效会话，退出后原会话无法复用。
- 界面验收：在桌面和窄屏通过真实页面验证主流程、错误、密码显隐及键盘操作。

#### T001 交付记录（2026-11-15）

- **交付** — 注册后等待启用；管理员通过命令启用后，用户可用用户名或邮箱登录、查看账号并退出。启动和操作步骤见 [README](../README.md)，模块、数据边界和部署注意事项见 [架构评审](ARCHITECTURE.md#t001-实现与架构评审)。
- **接口与数据库** — 在 `backend/` 执行 `python -m pytest -q`，PostgreSQL 18.3 和 SQLite 各通过 5 项测试，覆盖表单和重复注册、并发重名、启用、登录、会话过期、退出和旧令牌重放。在 PostgreSQL 执行 `python -m alembic upgrade head` 和 `python -m alembic check`，迁移成功，模型与迁移无差异。
- **前端** — 在 `frontend/` 执行 `npm.cmd run build`，类型检查和构建通过。通过 Uvicorn 和 Vite 运行实际页面，使用 Playwright 检查 Chrome 1440 × 900 和 Edge 390 × 844，验证账号主流程、焦点、密码显隐、错误显示和网络重试。[UI 验收记录](UI_DESIGN.md)
- **待验证** — 当前环境缺少 Docker，Compose 启动待实测。Firefox 兼容性和完整读屏待验证。
- **Git** — 文档补记时 T001 仍在工作区，原有暂存项保留。本轮无暂存、提交或推送。

### T002｜角色、部门和基本访问控制（待开发，待细化）
- 关联：F001、F002；依赖：T001。
- 目标与范围：建立管理员、测试和开发的基础身份及部门关系，让不同用户进入授权功能；支持必要的账号启用、禁用和信息管理。
- 非目标：一次完成全部复杂权限组合。
- 验收方向：授权与未授权请求得到正确处理；账号、部门和权限变更按确认规则生效。具体角色与管理方式待定。

### T003｜创建和提交事项（待开发，待细化）
- 关联：F003、F009、F010；依赖：T001、T002。
- 目标与范围：测试人员保存草稿、填写 Bug 或需求的公共及专属字段并提交，可查看提交结果。
- 非目标：开发完整处理与验证流程；高级查询和通知。
- 验收方向：两类有效事项可提交并可查；公共及专属必填校验符合已确认 PRD；不完整草稿可保存。附件、删除和撤回规则在实现时确认并按规模拆分。

### T004｜开发接收与处理反馈（待开发，待细化）
- 关联：F004、F010；依赖：T002、T003。
- 目标与范围：测试提交时可指定开发；未指定的事项可由开发领取；开发查看、处理并提交说明。
- 非目标：测试验证和关闭。
- 验收方向：指定事项只能由指定开发处理；未指定事项可领取且不能被重复领取；处理结果可供测试查看。并发、转交等具体规则待确认。

### T005｜测试验证与重新处理（待开发，待细化）
- 关联：F005、F010；依赖：T004。
- 目标与范围：测试验证开发结果，通过后关闭；不通过填写原因并退回，开发可再次反馈供验证。
- 非目标：审批和外部部署。
- 验收方向：两条验证路径均可完成，结果和原因可追溯；未经授权或不符合状态的操作被拒绝。具体状态名称及访问规则待确认。

### T006｜查询、用户可见历史（待开发，待细化）
- 关联：F006、F009、F010；依赖：T003、T004、T005。
- 目标与范围：搜索、筛选、组合查询、分页、排序及查看事项处理和验证历史。
- 非目标：统计看板。
- 验收方向：查询结果与已确认条件及数据权限一致，空结果和历史记录正确展示。查询字段与可见范围待确认。

### T007｜消息通知（待开发，待细化）
- 关联：F007；依赖：T004、T005。
- 目标与范围：为指定开发、处理反馈及验证结果提供通知。
- 非目标：未确认的外部通知集成。
- 验收方向：约定事件向正确对象产生通知，用户不能查看他人受限消息；渠道、发送时机和重复策略待定。

### T008｜统计看板（待开发，待细化）
- 关联：F008；依赖：T005、T006。
- 目标与范围：展示事项与待办、处理情况。
- 非目标：未确认的指标和复杂数据分析。
- 验收方向：指标与测试数据及权限一致；统计口径与时间范围待确认。

### T009｜测试体系与回归扩充（待开发，待细化）
- 关联：F009、F010、F011；依赖：T003–T005 的可运行主链路；基础测试从 T001 开始。
- 目标与范围：整理需求到用例追踪，补齐 API、UI、端到端、权限、幂等、并发、一致性及浏览器兼容检查。
- 非目标：将所有测试都变成 UI 自动化或虚构结果。
- 验收方向：核心回归可重复执行，数据隔离，失败记录证据；覆盖与未覆盖范围可见，浏览器版本和覆盖边界待确认。

### T010｜缺陷闭环与质量流水线（待开发，待细化）
- 关联：F012、F013；依赖：T001 起可建立基础流水线，完整端到端报告依赖 T005、T009。
- 目标与范围：GitHub Issues/PR 跟踪真实缺陷；Actions 分层执行测试并归档报告、失败证据，逐步建立质量门禁。
- 非目标：未经确认自行设置具体质量数值门槛。
- 验收方向：约定触发器可运行测试并查看结果；缺陷可追溯修复及回归；门禁失败和合并限制通过仓库规则配置验证。频率与口径待确认。

## 后续交接
确定卡片层次和当前功能细节后进入 UI 设计，并在设计时确认项目名称；用户确认设计后提供英文项目名，待用户创建项目并提供路径。项目创建后核对并迁移 PRD、架构、任务和 UI 成果；新开发对话从用户指定的卡片开始，只细化该卡片。
