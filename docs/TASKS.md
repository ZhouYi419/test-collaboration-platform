# 功能卡片与实施顺序

状态：2026-11-18 更新
依据：PRD v0.4 和已确认的技术组合。按各卡片记录的状态和验收标准执行。每次交付同步设计和执行适当的功能、接口、权限及自动化检查，并记录真实缺陷；不等所有业务结束再测试。

## 业务主线
测试人员提交 Bug 或需求 → 指定开发或由开发领取 → 开发处理并反馈 → 测试验证，通过后关闭或不通过后退回。

## 任务卡

### T001｜注册、登录与退出（已完成）
- 关联：F001；依赖：无。
- 目标与范围：用户能注册、登录和退出；建立应用运行、数据库及基础测试方式。
- 非目标：完整用户管理、角色和业务功能。
- 注册验收：四项必填；邮箱格式、密码长度、密码一致及账号标识唯一性由服务端校验。有效提交后展示等待启用提示和返回登录入口。
- 登录验收：错误凭据显示统一提示；正确凭据的待启用账号提示联系管理员。管理员运行启用命令后，用户名和邮箱均能登录并访问账号页。
- 会话验收：未登录、已退出和已过期的会话访问受保护接口返回 401。刷新保留有效会话，退出后原会话无法复用。
- 界面验收：在桌面和窄屏通过真实页面验证主流程、错误、密码显隐及键盘操作。

### T002｜角色和基本访问控制（已完成）
- 关联：F001、F002；依赖：T001。
- 目标与范围：建立管理员、测试和开发的单角色身份。管理员查看账号、分配角色、启用和停用普通账号。用户在个人账号页查看当前角色。
- 非目标：一次完成全部复杂权限组合。
- 验收：服务器操作人员能看到并使用「管理员授权」页面。没有服务器操作权限的账号看不到入口，访问页面或直接调用接口时被拒绝。未登录请求返回 401，已登录但无权限的请求返回 403。管理员可为普通账号分配角色并启用或停用，普通用户只能查看自己的账号。停用后全部旧会话失效，重新启用后须重新登录。已启用且未分配角色的账号可登录和查看个人账号。

#### T002 已确认的业务规则

1. 服务器操作人员在专用网页授予管理员角色。该页面只向具备服务器操作权限的账号开放。账号管理页面向管理员，编辑范围为普通账号。平台不设部门，账号采用单角色。
2. 新账号注册后待启用、未分配角色。管理员选定测试或开发角色后可启用，也可更换已分配的角色。角色变更在下一次鉴权时生效。普通用户只能查看自己的用户名、邮箱和角色。
3. 停用立即撤销该账号的所有会话。重新启用后用户需重新登录，旧会话无法恢复。
4. 已启用且未分配角色的账号可登录并访问个人账号页，角色显示「未分配」。分配角色后获得对应权限。

原型和授权流程已获用户确认。[T002 UI 评审](UI_DESIGN.md#t002-原型评审)

### T003｜创建和提交事项（已完成）
- 关联：F003、F009、F010；依赖：T001、T002。
- 目标与范围：测试人员从「我的事项」创建、续编或删除本人草稿，直接提交或从草稿提交 Bug 或需求，并查看已提交详情。草稿及直接提交均支持附件。
- 范围边界：指定开发与领取由 T004 交付；开发处理、测试验证、高级查询和通知按后续任务卡交付。
- 表单与状态验收：不完整草稿可保存，重新打开可继续填写。Bug 和需求按各自规则校验必填字段，失败保留已填写内容。直接提交或草稿提交后，列表和只读详情均显示「待领取」。连续点击或请求重试只产生一条已提交记录。确认删除草稿后列表移除该条，取消确认可继续编辑。
- 字段验收：优先级下拉按 P0、P1、P2、P3 排列，列表与详情显示所选等级。Bug 发生环境下拉仅提供 `dev`、`uat`、`prd`，提交后详情显示所选环境。服务端拒绝枚举范围外的值。
- 附件验收：草稿及直接提交可添加支持类型的附件，每条最多 5 个、每个最多 10 MB。类型、大小及数量越界时局部提示并保留其他内容，合法附件可移除或在详情下载。提交结果与附件保存结果一致。
- 权限验收：未登录请求返回 401，已登录的非测试角色返回 403，读取或修改他人事项及其附件返回 404；状态不允许的写入失败。测试人员只能在列表中看到自己的事项。
- 界面与数据验收：桌面和 390 像素窄屏通过真实页面操作两类表单、草稿、附件、详情、删除和失败重试；检查 320 像素宽度下的溢出。用空 PostgreSQL 库执行 `alembic upgrade head`，检查迁移与模型一致。
- 业务范围、附件限制及原型已于 2026-11-17 确认。[T003 原型评审](UI_DESIGN.md#t003-我的事项原型评审)

### T004｜开发接收与处理反馈（已完成）
- 关联：F004、F009、F010；依赖：T002、T003。
- 目标与范围：测试人员可选填负责人。开发查看并领取未指定事项，负责事项从「待处理」流转至「处理中」和「待验证」。提交人可查看处理反馈。
- 指定验收：新建或续编草稿可选已启用的开发，指定后只进入该开发的待办。提交时候选账号已停用或角色已变更，校验失败并保留已填写内容。留空提交后进入待领取。
- 领取及权限验收：已启用的开发可打开待领取事项详情和附件。不同开发同时领取只有一个成功，失败方刷新列表后看不到该事项。指定或领取后用另一开发和另一测试账号直达详情、下载或发起写操作时被拒绝。原提交人及负责人可继续查看和下载。
- 处理验收：仅负责人能从待处理开始，处理中提交非空说明。跳过状态、空说明及越权写入被拒绝。写入失败保留内容，重复请求保持单次有效状态变更。待验证的详情展示负责人、说明与反馈时间。
- 界面及数据验收：桌面和 390 像素窄屏实际操作指定、领取、开始处理和提交反馈，检查 320 像素宽度下的溢出。用空 PostgreSQL 库验证合并后的建库基线。
- 流程和可见范围已于 2026-11-17 确认，用户于 2026-11-18 确认当前原型并授权实现。测试验证、退回和关闭由 T005 交付。[T004 原型评审](UI_DESIGN.md#t004-开发事项原型评审)
