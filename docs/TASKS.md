# 功能卡片与实施顺序

状态：2026-11-15 更新
依据：PRD v0.2 和已确认的技术组合。按各卡片记录的状态和验收标准执行。每次交付同步设计和执行适当的功能、接口、权限及自动化检查，并记录真实缺陷；不等所有业务结束再测试。

## 业务主线
测试人员提交 Bug 或需求 → 指定开发或由开发领取 → 开发处理并反馈 → 测试验证，通过后关闭或不通过后退回。

## 任务卡

### T001｜注册、登录与退出（已完成）
- 关联：F001；依赖：无。
- 目标与范围：用户能注册、登录和退出；建立应用运行、数据库及基础测试方式。
- 非目标：完整用户管理、角色和业务功能。
- 注册验收：四项必填；邮箱格式、密码长度、密码一致及账号标识唯一性由服务端校验。有效提交后展示等待启用提示和返回登录入口。
- 登录验收：错误凭据显示统一提示；正确凭据的待启用账号提示联系管理员。管理员运行启用命令后，用户名和邮箱均能登录并访问账号页。
- 会话验收：未登录、已退出和已过期的会话访问受保护接口返回 401。刷新保留有效会话，退出后原会话无法复用。
- 界面验收：在桌面和窄屏通过真实页面验证主流程、错误、密码显隐及键盘操作。

- **前端** — 在 `frontend/` 执行 `npm.cmd run build`，类型检查和构建通过。通过 Uvicorn 和 Vite 运行实际页面，使用 Playwright 检查 Chrome 1440 × 900 和 Edge 390 × 844，验证账号主流程、焦点、密码显隐、错误显示和网络重试。[UI 验收记录](UI_DESIGN.md)

### T002｜角色和基本访问控制（已完成）
- 关联：F001、F002；依赖：T001。
- 目标与范围：建立管理员、测试和开发的单角色身份。管理员查看账号、分配角色、启用和停用普通账号。用户在个人账号页查看当前角色。
- 非目标：一次完成全部复杂权限组合。
- 验收：服务器操作人员能看到并使用「管理员授权」页面。没有服务器操作权限的账号看不到入口，访问页面或直接调用接口时被拒绝。未登录请求返回 401，已登录但无权限的请求返回 403。管理员可为普通账号分配角色并启用或停用，普通用户只能查看自己的账号。停用后全部旧会话失效，重新启用后须重新登录。已启用且未分配角色的账号可登录和查看个人账号。

#### T002 已确认的业务规则

1. 服务器操作人员在专用网页授予管理员角色。该页面只向具备服务器操作权限的账号开放。账号管理页面向管理员，编辑范围为普通账号。平台不设部门，账号采用单角色。
2. 新账号注册后待启用、未分配角色。管理员选定测试或开发角色后可启用，也可更换已分配的角色。角色变更在下一次鉴权时生效。普通用户只能查看自己的用户名、邮箱和角色。
3. 停用立即撤销该账号的所有会话。重新启用后用户需重新登录，旧会话无法恢复。
4. 已启用且未分配角色的账号可登录并访问个人账号页，角色显示「未分配」。分配角色后获得对应权限。

原型和授权流程已获用户确认。[T002 UI 评审](UI_DESIGN.md#t002-原型评审)

#### T002 交付记录（2026-11-15）

- PostgreSQL 18.3 和 SQLite 各通过 7 项 `python -m pytest -q` 回归测试。测试从合并后的建库基线创建空库，覆盖单角色校验、角色变更、停用、重新启用和越权行为。
- 真实服务的授权列表和授予接口均拒绝无服务器操作权限的应用管理员和普通用户，返回 403。未登录直接调用返回 401。测试同时确认伪造身份请求头无法授予角色，越权请求前后目标账号的角色和状态一致。
- 在 PostgreSQL 运行 `python -m alembic upgrade head` 和 `python -m alembic check`，迁移成功且模型与迁移无差异。`npm.cmd run build` 通过类型检查和构建。
- 在真实 PostgreSQL 上用 Playwright 操作 Chrome 桌面 1440 × 900 和 Edge 窄屏 390 × 844，验证授权入口显示、确认、失败后重试、无权限页面、普通账号启停及旧会话失效。核对了对话框焦点和 Escape 关闭。[UI 验收](UI_DESIGN.md)
- 新版 UI 接入账号管理、管理员授权和我的账号。使用 PostgreSQL 独立 schema 回归普通账号启停、授权失败重试、账号分页、移动面板和角色提示位置。授权列表与授予接口仍分别通过未登录 401 与无服务器操作权限 403 的验证。
- Compose 启动、Firefox 和完整读屏待验证。

### T003｜创建和提交事项（待开发，待细化）
- 关联：F003、F009、F010；依赖：T001、T002。
- 目标与范围：测试人员保存草稿、填写 Bug 或需求的公共及专属字段并提交，可查看提交结果。
- 非目标：开发完整处理与验证流程；高级查询和通知。
- 验收方向：两类有效事项可提交并可查；公共及专属必填校验符合已确认 PRD；不完整草稿可保存。附件、删除和撤回规则在实现时确认并按规模拆分。

### T004｜开发接收与处理反馈（待开发，待细化）
- 关联：F004、F010；依赖：T002、T003。
- 目标与范围：测试提交时可指定开发；未指定的事项可由开发领取；开发查看、处理并提交说明。
- 非目标：测试验证和关闭。
- 验收方向：指定事项只能由指定开发处理；未指定事项可领取且不能被重复领取；处理结果可供测试查看。并发、转交等具体规则待确认。

### T005｜测试验证与重新处理（待开发，待细化）
- 关联：F005、F010；依赖：T004。
- 目标与范围：测试验证开发结果，通过后关闭；不通过填写原因并退回，开发可再次反馈供验证。
- 非目标：审批和外部部署。
- 验收方向：两条验证路径均可完成，结果和原因可追溯；未经授权或不符合状态的操作被拒绝。具体状态名称及访问规则待确认。
